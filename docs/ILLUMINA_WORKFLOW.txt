Illumina workflow extraction and historical connections
Development implementation — 4 November 2026

Status
The typed representation and reviewed method-level dispatcher are implemented
and software-tested. Fresh native scientific validation is still pending; these
changes do not retroactively improve or re-review the archived extractions.
The larger transcriptomics run is gated on the bounded pilot and reviewed method
identity. An extracted workflow is not an established evolutionary connection.

What we are building
Each scoped method gets a source-supported workflow at Illumina's diagram-level
detail. A later paper-guided stage records which earlier procedure it adopted,
what it changed, and where that change appears in the two workflows. The atlas
may have disconnected methods and multiple contributors to a later method.

What State, Operation and Flow mean
State = the actual preparation, retained fraction, collection or dataset at the
input or output of a source-described procedure. It describes what exists there.
An RNA-DNA hybrid can be ONE State with two named constituents; that does not mean
two separated fractions. Several intact droplets can be one collection State,
without claiming that their contents have mixed. A biological target is not
necessarily the material processed or the molecule that reaches sequencing.

Operation = one source-described action or grouped procedure performed on exact
inputs, producing, selecting, moving or observing exact outputs. It is an instance
in this method, not a universal reusable label. A reagent or goal is not an action.
A block can remain composite when the source does not establish its inner steps.

Flow = the evidenced directed connection between these records:
  State -> Operation: material_input or data_input
  Operation -> State: material_output or data_output
  Operation -> Operation: precedes, meaning ordering without asserting transfer
An arrow between two methods is a separate scientific relationship, not a Flow.

Construction rules supplied to the author AND reviewer
1. Identify the source's action blocks before creating nodes. Do not turn every
   caption, molecular icon, catalyst or arrow into an Operation.
2. Identify each block's actual input and output preparations/datasets. Reuse a
   shared interface State between consecutive blocks when the source establishes
   that it is the same intermediate; different labels alone do not create copies.
3. Preserve independent routes. Coexisting molecular classes stay within a State
   unless the source supports independent handling. A common operation caption
   on two branches does not establish pooling or one joint reaction.
4. Split a source block only for an evidenced routing distinction, consequential
   interface, attribution distinction or the specific design change being studied.
   Otherwise keep the source's grouped procedure. Do not expand a full recipe.
5. Record relevant facts with their subjects and support. Missing properties mean
   not recorded, never absent, unchanged or inferred from familiar protocols.

What the new contract changes
State.properties replaces free-text State.features for new records. Assertions
identify their subject (the preparation itself or an exact named constituent),
property, value and evidence. Material chemistry cannot be assigned to a dataset.
A broad source boundary such as total RNA is legitimate without invented ends,
strandedness or composition. Named constituents are optional, not a compulsory
chemical inventory. Source captions remain separate from scientific labels.

Operation.input_roles identifies what each input or named constituent does here:
for example RNA as template and hybridized DNA as primer within ONE input State.
Roles are local to this action, not permanent molecule categories. Operation.effects
records supported changes for its exact inputs/outputs; grouped effects do not
establish all-to-all molecular derivation. Resolution and output grouping make
composite blocks and distinct output routes explicit.

The controlled property/role fields improve retrieval, but Operation labels remain
local descriptions. They are not a completed shared operation vocabulary, semantic
hash or proof of cross-method equivalence. Expert/model source interpretation is
still needed to determine whether two procedures share a mechanism.

Why these rules were chosen
The recorded source review exposed concrete counterexamples. Cap-selected cDNA
does not retain an RNA cap: origin/selection differs from current chemistry.
cP-RNA diagrams show coexisting end chemistries, not automatically separate
fractions. CITE-seq uses reverse transcriptase to copy RNA and synthetic DNA;
an enzyme name alone cannot determine template identity. Smart-seq comparisons
can involve reagent/condition changes despite a largely shared schematic.
See experiments/representation_review_20261104/source_review.json for reading
scope; these are source-informed design lessons, not a new full-paper benchmark.

Current call order and files to read

1. Plan one job per scoped method, with all relevant source depictions.
   experiments/transcriptomics_revision_20261104/planning.py:
     prepare/subset -> WorkPlan -> PlanReview -> admit
   native_planning.py: execute -> prepare_inputs -> author/reviewer stages ->
     validate_artifact -> write_workflow_bundles
   Planning reads original registered cards/images/text. Name matches only
   nominate identity questions; they do not merge methods. Every source receives
   a disposition. Independent review binds the exact plan and source evidence.
   Three depictions of one reviewed implementation become one work unit.

2. Reopen the reviewed plan, then extract each method.
   experiments/transcriptomics_revision_20261104/extract_plan.py:
     load_plan -> execute -> extract_registered_workflow
   src/genomics_discovery/illumina/extraction.py:
     extract_registered_workflow -> build_prompt -> worker.run -> validation
   The dispatcher explicitly selects illumina_diagram/1.1. A unit supplies its
   scope, original source cards, namespaced source registry and diagram images.
   Prior extraction assertions are not supplied as scientific evidence.

3. Independently review each candidate and allow one supported correction cycle.
   representation.py: StructuredDiagramExtraction and STRUCTURED_INSTRUCTIONS
   prompts.py: build_prompt combines shared, role and version-specific instructions
   models.py: validate_extraction, review_targets, validate_review, review_outcome
   Fresh typed candidates require illumina_diagram_review/1.2. Review covers graph
   construction, every State property, aggregate omissions, labels and Operation
   roles/effects. Older review versions cannot admit a new typed candidate.
   Python checks IDs, types, scope, source quotes, file pins and complete review
   coverage. These checks do not establish biological truth by themselves.
   Missing evidence retains a research hold; it does not trigger unchanged reruns.

4. Publish and inspect the reviewed workflows.
   graph.py: build_graph -> reopen each artifact/review/source binding -> graph
   graph.py: protocol_text renders readable text deterministically from that data
   Supported records are queryable; held records remain diagnostic. get/group
   preserve structured assertions and their semantic-review context.
   Tools: list, workflow, get, neighbors, walk, search, group, protocol.
   group returns connected Operations, boundary States and evidence; it does not
   establish a reusable component, substitution compatibility or ancestry.

5. Investigate historical connections as a separate stage.
   experiments/citation_lineage_pilot/{run.py,prompts.py,models.py} provides the
   existing bounded citation nomination/retrieval/analysis/fresh-review pilot.
   illumina/relationships.py defines method_development and component_adoption
   separately from mechanistic_precedent, shared_mechanism, shared_purpose and
   comparison. Only documented development/adoption goes in the historical layer.
   Inspect the later citation context and earlier demonstration. Record retained
   procedure, before/after change, exact affected Operations, limitation, measured
   benefit/comparator, trade-offs and evidence. A citation or earlier date alone
   is insufficient. Expand only the workflow block whose detail the claim needs.
   illumina/history.py queries reviewed relationship outputs; it does not infer
   history. Automatic recursive full-atlas relationship discovery is unfinished.

What a new run writes
Planning: plan.json, review.json, worklist.json, state.json, pinned inputs and
  workflow_bundles/ (one source bundle per reviewed method work unit).
Extraction: inventory.json, state.json, RESULT.json and atlas.json.
Each method attempt: card.json, source_registry.json, extraction.json, review.json,
  graph.json, workflow.txt and stages.json. attempts/ retains exact prompts,
  schemas, input pins, delivered images and native command/events/output files.
The agent authors structured JSON. Python validates it, projects it into a graph
and renders workflow.txt; it does not ask another model to summarize the JSON.

Tools available to workers
Actual diagrams are attached. Source helpers list registered sources and retrieve
bounded text by ID/query. Self-check commands use the same required schema and
source rules as host admission. Sources and prior attempts are read-only. New
facts need registered source support; no recalled protocol detail is silently
promoted into the graph. Card/diagram evidence supports baseline extraction;
primary papers support consequential corrections and historical claims.
