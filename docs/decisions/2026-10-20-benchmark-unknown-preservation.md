# Account for reference unknowns separately from known obligations

An extraction can cover every stated reference obligation while dropping a consequential unknown or turning it into an unsupported answer. Known-fact coverage therefore cannot establish preservation of uncertainty. This criterion applies to every scoped protocol graph, including a later graph produced by the extraction harness; it is not tailored to particular methods, labels or graph sizes.

New graph assessments use `protocol_benchmark_assessment/1.1` (`BenchmarkAssessmentV2`). Each `ReferenceUnknown.id` requires exactly one `unknown_checks` row with `unknown_id`, `outcome`, `targets`, `rationale` and scoped `evidence`. Outcomes are `retained`, `partial`, `missing`, `reference_revision_needed` and `unassessed`. There is no automatic `resolved` outcome. Evidence challenging a reference unknown requests reference revision and renewed source review; it cannot silently replace the reference or receive preservation credit.

Retained/partial judgments require existing qualified graph witnesses, including `gap:ID` for an unresolved gap or exact state, operation, flow, module or resolution targets. The reviewer assesses whether those records preserve the question, context, consequence and next-evidence need. Target presence and matching text alone do not prove this. The representation remains the existing `Workflow`: an unresolved gap or a qualification in a relevant record is sufficient when scientifically appropriate. No extra reaction stages, intermediary states, module vocabulary or prescribed node count are introduced.

Every non-abstaining judgment must inspect the reference unknown's declared passage scope. Exact cited quotes and passage IDs are validated against the bound packet and the assessment's inspected passages. A scoped absence judgment can use that declared inspection without inventing a quote saying that information was absent. Quote integrity and accounting remain mechanical checks; source entailment remains a reviewer judgment.

Unknown preservation has its own denominator and outcome counts. Partial, missing, revision-needed and unassessed rows earn no full-retention credit. Zero unknowns is `not_applicable` with a null fraction. New reference construction withholds positive projection when unknown preservation is incomplete; known-obligation scores and the failed uncertainty assessment remain archived separately. Declared factual-audit row fractions stay separate, and whole-graph precision is always withheld.

`BenchmarkAssessment` and `GraphReviewAssessment` retain their exact 1.0 schemas and canonical digests. New wrapper `GraphReviewAssessmentV2` requires an explicit 1.1 assessment version; version-aware parsers read both formats without upgrading old objects. Legacy unknown preservation is `not_assessed`, including after re-rendering a report. CLI schema exports `assessment-v2` and `graph-review-v2` expose the new contract; generic check/score commands dispatch archived versions. Frozen native runtimes and records remain unchanged.

The criterion must also be used when later evaluating extraction-harness outputs: give the independent evaluator the same frozen reference, packet and exact extracted Workflow, obtain assessment 1.1, and apply the same exhaustive unknown accounting. The extractor's graph structure may differ; witnesses remain many-to-many and source judgments decide adequacy. Reference construction sees its reference and tests self-consistency. It does not become blind harness evaluation merely by adopting this criterion, and model-authored/model-reviewed outputs do not become human gold.
