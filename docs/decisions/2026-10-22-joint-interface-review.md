# Inspect the operation and its actual interfaces together

The clean baseline DBiT extraction asserts optional imaging during either barcode
flow, but assigns it only a State explicitly defined after the second flow. Its
first reviewer supported the operation and input edge. The second reviewer
rejected this unchanged association after an unrelated resource-only revision.
The underlying sources were available throughout. The initial host audit also
underclassified the issue as advisory; its earlier bytes and reassessment remain
recorded. A correct post-second-flow subroute does not support every timing claim
that the record asserts.

The observable failure is inconsistent cross-field assessment. We cannot infer
the first reviewer's internal cause. Adding a new State type, another agent or a
keyword-based timing rule would not establish source applicability. The existing
`query` tool already returns an Operation, its actual input/output States,
bindings, incident Flows, predecessors and consumers.

The development reviewer prompt now advertises that tool and directs joint
inspection of those records with contextual sources. Equivalent programmatic
inspection is allowed; it does not require one subprocess per Operation. This
changes neither the stored graph nor its acceptance gates. It is a task-specific
instruction clarification, not a demonstrated semantic guarantee or a new graph
algorithm.

The routing test uses a candidate path containing spaces. Eighty-five existing
runtime/scope checks passed after the change. A matched native sentinel must
compare the previous and revised prompts on identical pinned input graphs and
source requirements, using `review_only` with no correction or previous review.
Expected defect locations and source-checked supported interfaces remain host
only. Count localized detection and supported-interface retention separately;
generic rejection and blanket abstention cannot pass both. One exposed case and
one sample per configuration cannot establish a general improvement. No current
source-only extraction receives this new instruction retroactively.

## Observed evaluation

The [matched native pair](../../provenance/experiments/joint_interface_review_20261022/paired_native_results.json)
completed in job48948650. Both configurations caught the same timing defect and
retained all four supported connections. The revised reviewer visibly executed
joint Operation/State/incident-Flow inspection programmatically, but this did not
yield a detection advantage in the single pair. Retain the instruction as explicit
use of an existing tool and test it within fresh extraction; do not present it as
a validated accuracy improvement. No further agent or review round is added.
