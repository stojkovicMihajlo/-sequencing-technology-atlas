HISTORY HARNESS: INPUT AND RELATION CONTRACT
Decision under audit6November2026; no extraction prompt/runtime changes.

Observable inputs: accepted exact-version workflow artifacts, original registered
papers, citation contexts, curated method/publication assignments and the existing
relation glossary. A paper citation nominates investigation; it does not establish
method identity, adoption, improved performance or a valid interface transfer.

Target: a directed, scoped contribution from an evidenced earlier implementation
to a later one, separately reviewed against both source papers and located in the
workflow. Multiple contributors/changes are allowed. Unconnected methods remain.
Similarity and comparisons are separate layers; they are not ancestry edges.
No earliest-invention claim or proven interchangeability follows from this data.

Permitted history types remain method_development and component_adoption, with
existing definitions in illumina/relationships.py. Before/after descriptions,
retained arrangement, consequences and qualifications stay source-grounded prose.
Do not multiply edge types simply to label each reagent/stage or silently encode
improvement into a historical relation. Finer change categories can be analyzed
later without changing the source claims. Do not force a parent for main novelty.

Live alternatives:
1. Classify citations directly as graph edges, versus use citations as candidates
   then independently inspect the cited demonstration and workflow endpoints.
   Choose the latter because our edge must explain an experimental transition.
2. Read the moving extraction batch, versus freeze accepted rows and original
   artifact bindings in an immutable snapshot. Choose snapshot; the full job must
   keep running and its newly accepted workflows can enter later snapshots.
3. Require a legacy source.original field, versus recover the declared article
   from hash-pinned curated source-package records. Adapt input handling; never
   locate an original by title resemblance, file basename or guessed paths.

principle; no code copied. Neither claim equivalent production behavior nor
attributable guarantees from its smoke tests.

originals and unrelated pinned files; distinguish classification duplicates from
method versions; snapshot only admitted workflows and never mutate active batch;
reopen all source/native/admission pins. Bibliographic matching only creates a

adopted contribution, retain interface qualifications, and allow no established
relation. Native pilot must show actual source access, reviewer decisions and
before-to-after reconstructability, not only valid JSON or a connected graph.
