Evolutionary relationships — user clarification,12November

Main interpretation: B builds on a specified contribution of A. The contribution
can be unchanged, adapted, moved to another substrate/stage, or redesigned across
several coordinated changes. The three active relation labels remain
 documented_reuse, mechanistic_precedent, comparison. These describe why methods
are connected, not an invented exhaustive taxonomy of experimental changes.
Detailed compared_feature/before/after/consequence records explain the change.
Generic software/reference use is supporting context. Assay-defining encoding,
decoding or error correction can be an integral contribution with source proof.

Atlas presence is not required for acceptance. Review first checks the complete
curated method catalogue. Resolved known identities require actual earlier-paper
evidence, matching assigned publication and pinned implementation metadata.
Identified absent methods retain a name+paper-bound unextracted placeholder and
an atlas-addition queue entry. Ambiguous identities remain explicit; same names
or publication alone never force merging. Exact earlier Operation mapping is
optional. Scientific source artifacts remain unchanged.

Technical fragmentation prevention: the graph joins independently reviewed
canonical method IDs to their existing accepted workflow node. It preserves the
specific contribution on the edge and checks catalogue-entry fingerprints.
Metadata/version conflict and unsupported identity remain diagnostic issues.
CONNECTIVITY.json records weak-component sizes, unresolved contribution endpoints,
isolated investigated methods and missing published histories. It is a diagnostic,
not an objective to connect all nodes. ATLAS_ADDITION_QUEUE.json preserves missing
method work. Synthetic regression proves A->B->C connects across separate source
neighborhoods and rejects wrong-paper/changed-scope/self-version joins.

Parallelism: --agents N (legacy --workers N) controls independent method workflows.
Omitting it creates one slot per selected method, up to50. Author/reviewer phases
inside one method remain dependent. New50-method job explicitly sets50, excludes
four already-running histories and known provider stops, and requires exactly50
accepted, JATS-source-ready methods before model calls. Metadata lookup includes
273curated named methods; these are not273extracted workflows or new agent seeds.

Validation:234combined tests passed before deployment; independent50-process
barrier tests verify actual concurrency in orchestration. Scientific results and
actual running-worker counts must come from the new job, not software tests.
