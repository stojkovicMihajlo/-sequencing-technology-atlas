Prior information-effect work
The 8 November optional local_conditions_v1 definition explicitly required truth
for every input condition and separation of reporter from interpretation. Its
six Pseudo-seq trials found clearer standalone RT fields in 3/3 refined versus
1/3 baseline outputs, but the earlier false mock-control claim recurred in neither
arm. This was a bounded clarity finding, not a demonstrated hallucination cure.
The compact instruction 'Treatment and control can have different effects' was
less explicit. The revised FULL shared definition restores the mandatory local
condition requirement for author and reviewer.

Focused full-harness changes (not method-specific)
- prompts.py FIELD OWNERSHIP: name the supported material/data change rather
  than hiding it behind a generic process/prepare/treat label. Composite blocks
  stay composite. Unknown changes must not be invented.
- Description/mechanism explain the assay. Source comparisons, diagram/grouping
  decisions go in Evidence.rationale/Correction. Consequential uncertainty stays
  visible in the scientific account.
- information_effect names the distinction, carrier and measurement significance,
  applies to each actual condition/fraction, and distinguishes a recorded feature
  from later mapping/comparison/calibration/inference. Null remains permitted.
- Reviewer explicitly checks these obligations on the actual affected record.
- models.py field descriptions agree with the same definitions. JSON fields and
  types are unchanged. Material AND data operations remain allowed.
- representation.py asks for consequential attribution in the typed property
  when it is introduced/changed. No fixed property count or repetition everywhere.
