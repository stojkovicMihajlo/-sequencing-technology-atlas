Task contract frozen before implementation — 5 November 2026

Input: the unmodified human/LLM measurement request, its explicit constraints,
and an immutable snapshot of currently supported atlas workflows. A pinned
historical index is optional. All experts may search the wider literature;
absence from the supplied atlas cannot establish novelty or impossibility.

Output: proposed assay graphs using the atlas's State–Operation–Flow meanings,
explicit changes relative to located precedents, a claim/assumption ledger,
technical/novelty critique and revision. These are untested architectures, not
reported extractions, executable protocols or admitted evolutionary edges.

Material ambiguity: an extraction-only EvidenceSet requires support for every
claim. A novel arrangement cannot honestly satisfy that contract unchanged.
We retain the scientific graph vocabulary and typed property meanings but use
a distinct proposal schema and assessment ledger. We do not relax canonical
atlas admission. This is an epistemic boundary, not a cosmetic status label.

Live alternatives:
1. Full atlas in prompt vs selected graph/evidence retrieval. Select retrieval:
   explicit IDs, exact versions, bounded reads and visible retrieval trace.
2. Single author vs independent experts with shared review. Start with two
   independently assigned experts, a literature/citation investigator, one
   technical reviewer, and one revision; this is a
   demonstration configuration, not a validated optimal team size.
3. Import previous large opportunity engine vs reuse current transport/tools.
   Use current CodexWorker and atlas functions. The old engine targets a
   different graph and shares a Python package name with this checkout.

Success checks: graph structure and exact reference validity; preservation of
human constraints; source and hypothesis separation; explicit before/after
change and interface uncertainty; review bound to candidate digest; every
review issue receives a disposition in a revision; usable deterministic report;
recorded native prompts, tool calls, events, elapsed time and model usage.

Negative controls: missing source, stale atlas reference, wrong material/data
Flow, unsupported transfer labeled precedent, a critique for an older graph,
direct prior-art overlap, failed source/search access, and invented historical
parent. Structural tests cannot establish scientific truth or original novelty.

Evaluation: first demonstrate a real end-to-end run and inspect its failures.
Later compare equal-access text versus graph context, and one author versus
independent proposals plus review. Do not claim improved invention ability from
a successful software run or model-only assessment. Expert/wet-lab evaluation
remains necessary for scientific claims.

Primary-paper and pinned-code audit, adopted principles and rejected inferences
are recorded in docs/IDEATION.txt. No external code is copied into this module.

User addition: the dedicated literature/citation investigator examines the two
drafts before review. It checks the central measurement claim, each proposed
change and every cited literature document, records closest prior implementations,
and identifies unchecked graph claims. Existing experts retain independent search
access. Revisions do not inherit citation verification for changed claims.

Predeployment validation: 204 targeted software checks passed locally, including
current history/native-worker regressions. Offline graph rendering passed JavaScript
syntax/DOM interaction checks with a clearly marked synthetic fixture; an actual
browser screenshot was unavailable. This is not a live scientific demonstration.
