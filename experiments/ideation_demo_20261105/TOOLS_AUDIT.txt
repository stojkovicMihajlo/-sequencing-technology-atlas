IDEATION EVIDENCE AND GRAPH TOOLS — IMPLEMENTATION AUDIT
Date: 2026-11-05

Problem and local contract
The citation reviewer must be able to investigate a particular proposal using
exact source captures and reviewed atlas occurrences. Retrieval success,
document origin, bibliographic identity and claim entailment are separate facts.
The tools must preserve source bytes and qualifications, keep shared records
immutable, and return bounded context with lossless continuation.

Observed defect
source-add identifies a capture using URL plus text bytes, but previously rejected
the same capture when another agent gave a different title or content-level
description. source-fetch called source-add, so this metadata disagreement could
prevent an origin receipt from being recorded. This is an orchestration defect,
not evidence that the paper is unavailable or the proposal unsupported.

Decision before implementation
1. Keep the original source registration unchanged. Store alternative title and
   content-level declarations in capture_declarations.json, under the same lock.
   Return them explicitly without silently promoting excerpt to full text.
   Repeat captures with unchanged metadata remain idempotent. The sidecar records
   declarations, not an adjudication of which metadata is scientifically right.
2. Add change-context for one exact globally qualified historical claim. Join
   affected operation selections only when record ID and extraction hash match
   the loaded atlas. Return navigation: boundary IDs and explicit claim/group/node
   commands, not entire before/after workflows. The unchanged scientific claim,
   review, evidence and limits remain accessible through claim. External
   contributions and unavailable workflow versions stay explicit.
3. Do not add a vector store, an additional agent, or an equivalence classifier.
   Lexical search remains a shortlist; absence from it cannot establish novelty.

Observed: evidence gathering is question-specific, ranks contextual summaries,
and retains them in session state; paper search and citation traversal can gather
additional sources. Its local question swapping also makes this particular tool
unsafe to parallelize against the same mutable session without coordination.
ADAPT: bounded, question-directed evidence access with retained provenance.
REJECT as a domain rule: its fixed evidence-count guidance. It does not establish
how many sources demonstrate a novel genomics assay or a compatible interface.

REJECT: treating citation insertion or an exact quote match as scientific support.

Our additional requirement
An assay change must refer to the exact affected workflow version and retain its
input/output boundaries and unresolved qualifications. A paper-level retrieval
system does not supply that contract. change-context is a deterministic join over
already reviewed records, not a new scientific relationship or compatibility
judgment. Discovery outside the atlas still requires external literature search.

The first implementation eagerly included the entire reviewed claim and exceeded

characters, not tokens or a measured reduction in native reasoning time. The full
groups and claim can still be large; agents must request relevant records or use
result-read windows. No scientific qualification was rewritten to reduce size.

Limits and next observation
This is deterministic retrieval/join validation, not a new native ideation run,
scientific re-review, novelty benchmark or experimental assay validation. Capture
declarations are stage-local audit sidecars; original source records remain the
authoritative immutable identity. Cross-agent merge already preserves divergent
capture declarations, but does not infer that different URLs identify one paper.
No-match now explicitly means failure of literal retrieval within a potentially
incomplete capture, not a negative finding about the literature. Native runs
must still demonstrate that reviewers use the evidence, distinguish inaccessible
from unsupported claims and reformulate queries when needed.
