ATLAS TOOLS AND OBSERVED USE — 2026-11-05

Aim
Make exact atlas workflows and reviewed historical changes usable during ideation,
and distinguish tool availability from content actually returned. Do not require a
candidate to have an atlas parent or meet a quota of history calls. These are tool
and observation repairs, not evidence that graph conditioning improves inventions.

Legacy logs mark results complete before returning either content or an oversized

Changes implemented

1. history-list navigation
With the existing context-tool prefix, use:
  history-list <record_id> --depth 2 --offset 0 --limit 10
Limit is 1–20, explicit depth follows the existing history reader. Result data:
  view: navigation
  binding: exact atlas/extraction pins
  relationships: [{claim_id, relation, before: {id,name,kind},
                   after: {id,name,kind},
                   read_commands: [[claim,claim_id],[change-context,claim_id]]}]
  total, next_offset, other_direct_relationship_count, withheld_count
  read_history_command, boundary
This is a paginated list of already admitted historical claims, not a scientific
summary. claim returns statement, review, evidence and limits; change-context
returns version-bound before/after Operation groups and boundary State IDs.
Similarity is not silently promoted into ancestry. Unloaded history, missing
versions and an empty loaded neighborhood do not establish no predecessor.

2. Node/group provenance size repair
An actual Quartz-Seq add_rt_primer node was 96,210 serialized characters. Its
workflow's full provenance registry occupied 85,342 of them and included 72
sources. The selected scientific Operation itself occupied 1,615 characters.
Returning this entire registry with every node made a narrow lookup unnecessarily
expensive and pushed scientific information behind paging.

node and group now keep every scientific field, quotation, qualification and
full_source_registry_artifact unchanged. Their provenance view contains only the
sources cited in the selected returned content, with bibliographic, identity,
association/access-status and path/hash fields. A source_metadata_access record
names missing registry entries rather than inventing them, states the view's scope,
and provides atlas-source/workflow commands for the complete provenance.
No frozen graph or source registry is rewritten. This is deterministic projection,
not model summarization or dropping difficult scientific details.

On the unchanged real fixture, the same node becomes 12,858 characters with three
cited source metadata entries. Every non-provenance field and evidence-index entry
is identical. This is a character-size reduction, not a measured token-latency or
scientific-quality improvement. Large scientific records can still require paging.

3. Additive tool-delivery metadata
Successful context audit rows now record:
  delivery: inline | stored_pointer
  usage.kind: workflow_content | historical_claim_content | navigation |
              source_excerpt | source_metadata | result_window | other
  result_state, exact relevant record/node/claim IDs, and selected binding pins
  source excerpts: returned text length and source/version fields
  result windows: exact start/end/total characters
Failed calls retain their error rows. Literal no_match and history not_loaded are
not counted as successful evidence delivery. An oversized result is stored before
logging success, so a storage failure cannot look like a completed content return.
This does not instrument arbitrary native shell reads outside these tools.

4. Deterministic usage receipt
New src/genomics_discovery/ideation/usage.py:
  build_usage_receipt(run_dir, candidate_paths=()) -> dict
  usage_from_logs({log_name: exact_jsonl_text}, candidates={name: json_object})
Neither writes files. The pipeline caller may persist the returned receipt and
must not let an audit error hide a primary run failure.

CLI, with the repository on Python's module path:
  python -m genomics_discovery.ideation.usage RUN --candidate CANDIDATE.json

Receipt format ideation_atlas_usage/1 includes per-attempt action counts/errors,
navigation delivered, content delivered, no-match/unavailable findings, legacy
uncertainty, and pagination coverage. Complete pagination requires the union of
inline-delivered windows to cover the whole original result within that same log.
Repeated windows are not counted twice; different sessions cannot jointly receive
credit for reading a complete result. Partial content remains partial.
Candidate citations retain their exact location, record/node/extraction identity,
and whether that precise node delivery was observed in any supplied team session.
That is an access cross-check, not entailment or causal attribution. No exact-node
match can reflect broader workflow access, another channel or incomplete logging.
Historical navigation IDs remain separate from historical claim content IDs.
Candidates currently declare State/Operation references, not typed historical-edge
citations; the receipt does not manufacture a downstream historical citation.
