Bounded design team: development decision, 5 November 2026

Problem and boundary
The earlier two-design run consulted atlas nodes but history access failed. The
proposals also needed independent scrutiny of physical interfaces and claimed
benefits. A graph citation or successful program exit does not establish novelty,
scientific feasibility, or that the atlas improved a design.

Adopted contract before implementation
Preserve the existing proposed_assay/1.1 graph and Codex worker. Add a versioned
ideation_run/3 orchestration: coordinator assigns four distinct design mandates;
designers initially work independently; one recorded peer-critique round; a
literature/citation investigator; two independent specialist lenses (chemistry
and interfaces, measurement and benefit); synthesis review; at most one author
response/revision; fresh final review. Do not silently merge candidate graphs.
The designer count is configurable; four is an experimental resource choice,
not a scientific optimum. One peer round is a bounded collaboration experiment.

Messages bind exact candidate hashes and graph targets. Author responses account
for received comments and review issues. Dropped proposals remain recorded with
the reviewer reason. Specialist objections require an explicit disposition;
unresolved objections must survive synthesis. These are bookkeeping guarantees,
not proof that an LLM's scientific judgment is correct.

Memory and tools
Each stage receives explicit artifact paths and separately captured sources in a
fresh model session. It can read the required parts and search more literature.
No entire conversation/paper corpus is copied into every prompt. Preserve immutable
input pins, source identities, native events, prompts and stage receipts. Use
paginated history navigation followed by exact claim/change-context retrieval.
Record actual tool delivery separately from a candidate's declared references.
No quota forces unrelated atlas use or invents a predecessor.

Reference rationale
PantheonOS's explicit peer calls and separate child contexts motivate addressed,
recorded exchanges; its runtime is not drop-in compatible with CodexWorker.
ROBIN motivates proposal-specific literature investigation before disposition.
Our graph-bound issue accounting and material/information-interface checks serve
this project's assay-design task. See REFERENCE_AUDIT.txt for pinned code,
licenses, implementation limits and rejected alternatives. Do not vendor an
entire agent runtime or change the user's provider/account to imitate a paper.

Verification and experiment
Test four independent branches, stale/missing peer targets, exact author replies,
specialist objection loss, partial worker failure, final issue accounting,
history preflight and actual delivered-content receipts; retain legacy tests.
Run the same question and pinned atlas/history as the preceding experiment on
Qiu Sherlock with gpt-6.1-sol/xhigh. Do not carry previous ideas or audit answers
into the new run. Compare output/failure/latency/usage; this changes multiple
harness components and is not a causal ablation of team size or atlas benefit.
No claim of improved scientific validity before inspecting live outputs.
