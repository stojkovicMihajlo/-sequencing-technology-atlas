Information-effect definition experiment — Pseudo-seq, 8 November 2026

Definition tested
information_effect explains what information the output preserves, introduces,
makes recoverable or loses through THIS Operation, what carries it, and under
which input conditions that statement holds. It distinguishes an observed or
encoded feature from an interpretation requiring later comparison or inference.
Description says what is done; mechanism says how it works; information_effect
says what the output can tell us and what remains unresolved at this stage.

The refinement changes author instructions only. The exact text is definition.txt
and prompts.py:INFORMATION_EFFECT_LOCAL_CONTRACT. The production default remains
current; the refined option is local_conditions_v1. There are no paper-specific
examples in this added block and no prohibition on Python or shared wording.

Experiment
Six fresh Pseudo-seq workflows: baseline trials 01/04/06 and refined trials
02/03/05. Same card, diagram, registered primary text, schemas, source tools,
model gpt-6.1-sol, xhigh effort, and independent-reviewer instructions. Each trial
allows one author correction with a fresh reviewer. Neither earlier outputs nor
our evaluation notes are supplied as examples. Source retrieval outside the fixed
bundle is disabled for this controlled comparison. The baseline includes the
prior common branch-representation fixes; this isolates the added definition.

The saved first-author artifact is the submitted result AFTER the author's own
structural self-checks and BEFORE independent review. It is not necessarily the
first draft written to disk. Native logs and intermediate files preserve those
internal corrections. Changes are not made to the six trials during evaluation.

What the source-based assessment found
All 66 information_effect fields across six submitted first-author artifacts were
inspected together with their descriptions, mechanisms, typed effects, connected
States, and the registered primary-paper passages.

                                  Baseline       Refined
Original false mock-encoding claim   0/3            0/3
RT field clear on its own           1/3            3/3
New null information_effect fields     0              0

The clarity result is an engineering-agent judgment, not blinded human-expert
scoring. It is not a statistically established improvement or general accuracy
estimate. No definite condition-inappropriate claim was found in this focused
assessment. We cannot claim the refinement reduced hallucinations: the known
error did not recur in the baseline either.

Two baseline RT fields describe a treatment-specific chemical-to-endpoint effect
without making its condition explicit within that field. Their neighboring
fields correctly distinguish treated and mock RNA. These are local readability
problems, not demonstrated whole-graph false claims about mock chemistry.
The third baseline field is appropriately general and clear for both conditions.
All three refined RT fields are clear, either by spelling out each condition or
by making a shared statement that is valid for both.

Actual baseline trial04 field
"Converts a chemical feature of the RNA template into a cDNA termination boundary.
The reporter is the copied DNA sequence and endpoint, not a pseudouridine chemical
mark on cDNA."
This Operation processes both +CMC and mock inputs. The chemical feature applies
to the treated member; its description and typed effect supply that qualification.

Actual refined trial03 field
"For the +CMC member, chemical susceptibility is converted into a cDNA termination
boundary linked to RNA-derived sequence. For the mock member, endpoints represent
CMC-independent termination. A stop is not a Ψ call until sequence mapping and
the paired comparison; cDNA does not inherit the RNA adduct."

Both statements are preserved unchanged in the downloadable native results.
The useful improvement is explicit applicability and separation of reporter from
inference, not simply more words or more nodes.

What else happened inside the runs
All authors used Python to assemble JSON. This does not establish Python as the
cause of scientific mistakes. Three refined authors and one baseline author initially used material
components in data States; existing validation caught this and they corrected it.
One author passed card.json as the source registry to a check, then corrected the
path. Several reviewers initially treated a canonical candidate hash as a raw
file hash; assertions/binding checks rejected this. One optional jsonschema
import failed; the author used the project checker. These are recorded separately
in engineering_findings.json and the native event logs. They are not attributed
causally to the refined definition from this small experiment.

There is still representation variation: 10–12 Operations; separate condition
States in one baseline versus compact, explicitly separate collections elsewhere.
Trial06 starts with already poly(A)-selected RNA rather than adding its selection
as an Operation. These are not information-effect errors if scope, correspondence
and interpretation remain explicit. Two nonblocking Unknowns concern a clipped
cartoon (trial05) and catalogue-only circularization-bias evidence (trial06).

Decision
Keep the refined option available for the next controlled test; do not claim a
validated universal replacement from one known failure case. Keep independent
review and structural validation. A next evaluation should use different kinds
of information carriers and treatment/control structures, with both prompts
frozen before the new cases are examined. Review acceptance and a clear standalone
field should remain separate measurements.
