SOURCE_BUNDLE-001 — retrieval duplication addressed; acquisition consolidation deferred
Confirmed in SPLiT: the poster registration and selected-primary registration
contain identical full text, title, PMID, access level and URL. Their association
statuses differ. Both provenance IDs are retained. The source search now returns
identical text once only when all declared bibliographic fields and content
level match, lists every registration and its association status, and separately
reports registration count and distinct text-rendition count. The prompt flags
duplicate registrations as non-independent evidence. Different texts, titles,
PMIDs or content levels are never collapsed by this rule. Sources with no
bibliographic identity remain distinct. No model-based identity merging occurs.
Upstream acquisition can still cache/register duplicates, and comparison against
older runs remains confounded by source-bundle changes. This change does not
claim to resolve those separate scheduling/causal-evaluation issues.

SOURCE_RECOVERY-001 — still open; do not disguise as a correction
The current correction operates on a fixed registered source bundle. A reviewer
request for a missing supplement does not download/register it. Current prompts
make this boundary explicit; unresolved evidence stays held. A future recovery
task must obtain the actual missing material, preserve source identity/custody,
create a new bundle, then obtain fresh extraction/review. Rewriting unsupported
claims or re-running the same bundle cannot supply missing evidence. The targeted
seed path intentionally rejects source changes. Access restrictions and missing
documents require separate recovery, not a stronger author instruction.

EVIDENCE_SCOPE-001 — existing distinction retained; audit/calibration still needed
The extraction prompt already targets depicted assay architecture. A clear
diagram can support that architecture without demonstrating a missing reaction
mechanism. The historical relationship contract separately requires source
support for a scoped before/after change, attribution and consequences, and
distinguishes method development from component adoption and mere mechanism or
purpose similarity. Do not require an executable recipe for every architecture,
and do not reuse architecture acceptance as historical proof. No paper-specific
scientific criterion was added in this iteration. Reviewer consistency across
more technologies remains an empirical evaluation issue.
