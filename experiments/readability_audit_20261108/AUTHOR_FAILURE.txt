Why the Pseudo-seq author wrote Python, and what failed

FORENSIC FOLLOW-UP: observable cause and validation boundary
See failure_diagnosis.json for pinned files, observable command-event locations
and an offline replay using the exact archived runtime_01 Python sources.

The required mock-control evidence was returned before generation. The script's
quote-in-paper assertion checked literal occurrence, not whether a claim was true
for this treatment arm. After writing, the logged artifact inspection displayed
only Operation IDs and input/output IDs. The author also made other scientific
edits after its first structural check; it did not change the erroneous sentence.
This does not establish what internal checking the model attempted.

Replay results: both original and corrected records pass structural/source checks.
The actual original review produces needs_revision; the corrected review produces
supported. Swapping the corrected review onto the original record is rejected by
the candidate hash check. Negative controls with a nonexistent input State or
fabricated source quote are rejected. No new model calls were needed for this
diagnostic. Accepted historical records and production prompts remain unchanged.

The old extraction also repeated the same information_effect across its two RT
Operations, but its sentence described sequence copying and endpoint retention,
which applies to both arms. Thus shared wording and Python loops are not defects
by themselves. The precise defect is loss of a condition on a scientific claim.

The field definition was broad about information/carrier effects and did not
explicitly restrict this field to the local input condition. Multiple prose
fields can be independently correct or contradictory, and there is no enforced
author-side semantic reconciliation after JSON assembly. These are actionable
design weaknesses, not proof of the model's internal cause or a causal effect of
the latest prompt edits. The separate reviewer provided that reconciliation here.

Observed execution
The extraction harness launches a native Codex author with shell and file tools.
The EXECUTION prompt requires artifact.json, permits work in the assigned attempt
directory, and prohibits changes to package code, sources and other attempts.
It does not prescribe a particular file-writing method. That permission predates
the State-content revision. The author chose to generate build_artifact.py to
assemble the JSON record; the harness did not supply this scientific template.
The script was not a wet-lab protocol execution or a change to the harness.

Exact failure
The generated script iterates over plus/minus treatment arms. It correctly makes
the RT description and output-State attribution conditional on the arm. It fails
to do so for information_effect, reusing an explanation of modification-dependent
RT termination in the mock-control Operation. Thus adjacent fields contradict
one another. The mock-control paper passage was available and cited. This was
not a missing-source problem or a scientific permission granted by the prompt.

The first-author script is preserved at
pilot_results_01/correction_trace/author_construction.py, lines 95-107.
The first review, two-field correction and final reviewed record are preserved
beside it and in the complete job 51546953 archive. Reviewer target
operation:minus_rt names the incorrect information_effect and the supporting
paper:25192136 passages. The author correction changes that field and its matching
attribution-effect statement only. A fresh reviewer accepts the corrected record.

What the harness enforced
Structural/source checks accepted the JSON shape and references. They did not
prove that each natural-language claim applied to its local input condition.
Every author goes through independent review, which caught this error before
scientific admission. A successful JSON check was never the final acceptance gate.

What was underspecified or inconsistent
The choice of assembly technique was open. The scientific requirement to describe
the actual input, transformation and output was already present. Separately, an
old shared rule required distinct Operations for independent branches while newer
guidance permitted compact collections with explicit correspondence. That was a
real instruction conflict. Commit 8a7e7b1 aligned the rules. It does not establish
that this conflict caused the copied scientific assertion.

The follow-up, job 51547846, retained source bytes and used fresh author/reviewer
contexts. It produced 11 Operations, 12 States and 22 Flows and passed independent
review without correction. The treated and mock cDNA products have distinct
attribution statements. Its first author and final extraction are equal after
schema normalization. This is one observation, not proof that the error is gone.

Decision
Do not ban Python in response to this case: the same false reuse can occur in
directly written JSON. Preserve independent review of each local claim against
its inputs and source. Retain this observed error as a future semantic-review
test case. Do not add a Pseudo-seq-specific rule or claim that software tests
prove the biology. Broader improvement requires further fixed-source comparisons.

Remaining limitations
The new irCLIP text is clearer, but some attachment facts moved from structured
association properties into prose. Queries limited to typed associations would
retrieve less. Compact Pseudo-seq condition correspondence is partly prose;
component-level graph traversal was not tested. Neither issue is solved merely
by the independent review accepting the scientific description.
