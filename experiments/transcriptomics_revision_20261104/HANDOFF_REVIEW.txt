WHAT THE PIPELINE DOES
1. Consolidate source depictions into scoped method work units before dispatch.
   A catalogue card, poster row and collection figure are sources, not three new
   assays. Grouped names need applicability decisions. Existing reviewed source
   grouping is reused only at its recorded scope; identifiers are not semantic
   equivalence proofs.
2. Extract the depicted architecture, with targeted paper clarification. A State
   is material or data at a boundary. An Operation acts on specified input States
   and produces specified output States. A Flow explicitly links State->Operation
   or Operation->State, or records supported Operation ordering. Python rejects
   invalid types, nonexistent endpoints and disagreement between I/O and Flows.
   Preserve consequential carrier, attachment, location and molecular features.
   Do not expand routine washes/volumes unless they affect interpretation.
3. Review the architecture against its actual images and registered paper text.
   Corrections preserve the original depiction and primary-source explanation;
   corrected graph topology must actually agree with the correction. Unknowns
   are judged against this schematic scope, not an imagined complete recipe.
4. Read the later paper's citation contexts; nominate methodological references
   and explain exclusions. The host acquires nominated sources. The research
   agent checks the earlier demonstration and later attribution independently.
   It writes the contribution, before/after difference, retained arrangement,
   reason, reported consequence, limits, sources and affected Operations.
5. A fresh reviewer checks both scientific content and coverage. At most one
   author correction plus fresh review follows. Software checks exact quotes,
   IDs, source levels, review binding and uncertainty decisions. Accepted pilot
   claims become a separate relationship overlay; other claims remain withheld.
6. Read-only queries join loaded overlays only through exact workflow record ID
   AND extraction hash. Outside contributors remain external until method/version
   identity is resolved. Names or shared publications cannot silently merge them.

WHAT AN EDGE MEANS
method_development: a documented earlier assay implementation is a starting
point; identify the retained arrangement and revisions into the later assay.
component_adoption: a specified earlier contribution is demonstrably used or
adapted in the later workflow. It may be a feature inside one Operation or span
several. It does not imply inheritance of the enclosing assay.
mechanistic_precedent: relevant earlier demonstration without established actual
adoption. comparison: reported comparison, not ancestry. Similarity relationships
in the separate paired tool are also not historical edges.

These types describe the evidential relationship. They do not classify the
technical innovation. Preserve concrete descriptions first, then cluster changes
across the dataset. Do not force a unique parent, improvement, or common sequence
of assay stages. Several supported contributions to one method are legitimate.

REVIEW TEST ADDED TO THE EXISTING REVIEWER
Within finding.rationale, explain from the original sources:
  Starting with the earlier arrangement, retain X and change/adopt Y. This yields
  or preserves Z, which serves the next operation or measurement in this way.
Require only the scope of the claim. A component claim need not reconstruct the
whole assay. A paper-supported earlier description need not have graph IDs yet.
Request revision/evidence if this explanation requires an invented transfer,
unspecified consequential carrier/order, or unsupported causal assignment.
Routine missing settings do not automatically invalidate an architectural link.
This requirement is now in the prompt. It is not a deterministic scientific proof
and has not yet been exercised by a new native run under the changed wording.

REAL EXAMPLE: iCLIP -> irCLIP, WITHIN C12
Retained: recover protein-associated RNA from nitrocellulose using proteinase K
for downstream library construction.
Earlier implementation: the cited iCLIP protocol uses 37C recovery incubations,
including a urea-containing stage.
Later implementation: irCLIP uses an SDS-containing proteinase-K treatment at 50C.
Continuation: recovered adapter-ligated RNA proceeds through precipitation and RT.
Consequence: the paper reports improved recovery for the combined change.
Limit: this does not separately establish SDS-only or temperature-only benefit,
or prove the proposed explanatory mechanism. The entire assay's cell-input gain
cannot be assigned to this change alone.
C12 also records changes in digestion location, adapter functions, RT and
purification/circularization. The example above is one part, not the whole edge.
Sources: original irCLIP PMID27111506 and cited iCLIP protocol PMID24184352,
registered in irclip_history_01/inputs/sources.json. The archived C12 includes
their exact excerpts and the original model review.

HOW THE IDEATION ENGINE SHOULD USE IT
Given a desired capability, retrieve candidate methods, inspect their workflow,
then request the relevant change claims. Read the actual before/after arrangement,
tested result and limits; expand the affected operation group or primary sources
when an interface matters. Treat a reused property as demonstrated only in its
recorded setting. A proposed new interface is a hypothesis requiring verification.
The resulting idea should cite the retrieved claims and specify its own departure,
the intended capability, and the untested compatibility assumptions. The graph is
an evidence memory, not a menu restricting invention to old combinations.
Capability retrieval is currently lexical plus agent reasoning; no validated
semantic capability ranker or novelty score is implemented. A path through two
historical edges does not establish transitive transfer of their components.

REMAINING RELEASE BLOCKERS
1. Review-triggered source expansion. A reviewer can identify an excluded or
   unnominated reference, but the current correction loop cannot add its content
   to the immutable source bundle. Its output remains withheld if the omission
   persists. Separate source requests from wording corrections: acquire the exact
   requested source into a new registered snapshot, then research/review again.
   Existing acquisition remains mainly PubMed/PMC; publisher/DOI-only sources and
   supplements need explicit recovery. More unchanged-source iterations cannot
   solve unavailable evidence.
2. Exact predecessor identity binding. The paper-scoped earlier contribution is
   usable now, but attaching it to an existing catalogue method/version needs an
   explicit evidence-backed identity decision. Until then traversal stops at an
   external contributor. Do not resolve this through title similarity alone.
3. Native acceptance of the revised contract. Reuse completed source packets;
   do not repeat all 19 extractions. Test one multi-change development and one
   scoped adoption, plus misleading comparisons. Inspect the actual review text
   and retained limitations. Current software tests are not model-quality tests.
