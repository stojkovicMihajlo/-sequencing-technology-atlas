PURPOSE
Produce the transcriptomics portion of the sequencing technology atlas using the existing Illumina schematic representation and reviewed paper-based connections. This is a bounded production batch, not development of a universal extraction framework.

THIS BATCH

A repeated depiction is evidence for a method, not a new extraction job by default. Names, shared citations and hashes nominate/check records; they do not prove scientific identity.

Coverage: larger_01/source_scope.csv accounts for all478 source occurrences:48 selected,6 completed-pilot sources reused,10 held,414 pending. The existing source census and all earlier attempts remain unchanged.

CONNECTIONS AND CLASSIFICATION
A connection record preserves the earlier method/component, relationship type, exact design-change description, affected operations, limitation, reported gain, trade-offs, evidence and review outcome. One existing claim may contain several design changes.
Relationship types currently distinguish whole-method development, component adoption, mechanistic precedent and comparison. Shared mechanism/purpose comparisons also exist in the paired-method runner. Comparison or mechanistic similarity is not ancestry.
Change categories are deliberately unassigned. After collecting supported changes, review the actual descriptions, split multi-change claims where evidence supports it, and draft a small codebook with examples and exclusion rules. Assign multiple categories where needed; keep unresolved cases visible. Version these annotations separately so revising a category never requires re-extracting the workflow. Categories are research outputs, not predetermined universal axes.

HISTORY HANDOFF
This Slurm batch automatically extracts and reviews workflows. Existing citation_lineage_pilot separately traces reviewed methods through primary-paper citations. Before scheduling its next batch, verify each scoped method's actual primary source from PaperMatch; a related full-text paper is not automatically that method's primary paper. The current full-citation runner requires registered JATS bibliography. PDF-aware paired comparison does not provide PDF bibliography extraction. Do not silently select the first available full text or claim history ran when only extraction completed.

FOLLOW-UP SCOPE LESSON FROM THE COMPLETED HISTORY RUN
One of the three Drop-seq component-adoption claims describes ddPCR validation outside the extracted assay route; two describe components anchored within the assay workflow. All three remain inspectable with their exact qualification. Do not present the validation procedure as a predecessor of Drop-seq library construction. The classification pass should explicitly distinguish assay construction, analysis and validation context before aggregating evolutionary changes. Existing prose and operation anchors already expose this distinction, but there is not yet a dedicated context label. This observation does not change or relaunch the extraction batch.
