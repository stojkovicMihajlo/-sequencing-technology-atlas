Transcriptomics revision — 4 November 2026

Purpose
Revise the State/Operation extraction contract, test it on a bounded pilot, then
re-extract transcriptomics by scoped METHOD rather than source occurrence. Follow
primary citations in a separate relationship stage. Historical records stay intact.

Current planning status
planning.py creates a source census and candidate identity questions. It does NOT
infer accepted method identity from labels, citations or publication dates, and
does NOT start extraction. The initial 185 RNA-context source occurrences are not
185 methods. All remaining single-cell, DNA-poster and website records stay in the
scope review ledger so joint or cross-listed RNA assays are not silently omitted.
Supporting footer panels get their own disposition rather than becoming assays.

Input source scope
The compressed audit archive contains source metadata, not full original source
content. Each row points to source_registry.json and card.json in its preserved
Sherlock attempt directory. The author and independent reviewer must inspect the
registered diagrams/text there. Existing extraction summaries are not identity
evidence, and this planner does not include them in the census.

Candidate names are only retrieval leads
Whitespace, hyphen and case normalization nominates identity questions. It NEVER
merges work units. CapSeq/CAP-seq, grouped titles, shared references, and related
variants may collide. Same-paper evidence does not by itself establish one assay.
No candidate pair means only that this cheap retrieval missed it; the reviewer
also checks work units for duplicates and missing aliases.

Review output and gate
The planner authors WorkPlan with one disposition per occurrence, specific scoped
work units and answers to every nominated identity pair. The reviewer authors
PlanReview bound to the exact plan digest and assesses every source, unit and
identity decision. Both schemas are generated by the schemas command.
admit refuses incomplete coverage, unresolved duplicate candidates in extraction,
same-method duplicates scheduled separately, wrong-source references, stale review,
missing review targets and rejection. One source may support separately scoped
variants; grouped labels are not automatic aliases. Scientific sameness still
requires source interpretation, not the Python gate.

Admission produces a model-reviewed WORKLIST, not a validated workflow graph.
Source-file custody/access checks and the revised-extraction pilot gate still have
to pass on Sherlock before any large job. The immutable author/reviewer sessions
and inspected source pins must be archived by the caller. No scheduling count is
reported as a canonical number of transcriptomics methods.

Bounded native pilot
native_planning.py run PILOT_CENSUS OUTPUT is Slurm-only and uses the existing
CodexWorker with gpt-6.1-sol/xhigh. It loads and pins original source registries
and cards, verifies source-file custody, attaches registered diagrams, and exposes
bounded literal source retrieval plus a self-check command. Author and reviewer
use fresh native sessions. One source-supported author revision is allowed after
review rejection; process or source failures are not automatically retried.
The exact prompts, schemas, native transport, input pins and stage states remain
in the run directory. No original extraction graph is provided as evidence.

SourceEvidence uses the existing image/text Evidence contract plus record_id and
finding. Native validation checks exact quotes, source kind and per-side evidence,
and rejects metadata/title-only implementation identity. Independent review still
checks whether the passage/diagram actually supports the proposed consolidation.

Successful planning writes workflow_bundles/manifest.json. Each unit has card,
registered sources, image pointers, raw original cards, exact scope bindings and
artifact hashes. Sources are namespaced record_id::original_source_id so common
paper/image IDs cannot collide or silently overwrite different renditions.
The original primary references retain their scope and qualification. The caller
may pass these bundles to extract_registered_workflow after its separate pilot
gate. Full-batch planning still needs batching and a cross-batch identity check;
this bounded runner does not establish that all transcriptomics units are ready.

Batch planning and reconciliation
batching.py prepare accepts an explicit source selection (--rna-context,
--record-id, or --records-file). It follows candidate identity-neighbor links so
all depictions requiring comparison remain in one planning batch. Connected
components are never split. The default 12-occurrence cap is a practical context
setting, not a biological rule; an oversized component is held for an explicit
context-limit decision. Unselected sources remain pending scope review.

The prepared rna_context_batches/manifest.json selects the 185 RNA-context
occurrences plus 40 candidate identity neighbors: 225 sources in 19 planning
batches, with 253 other occurrences still pending screening. These are planning
batches, NOT 225 extraction jobs or a final transcriptomics method count. All
same-name candidate groups stay together. No oversized group occurred at cap 12.

batching.py run MANIFEST OUTPUT --batch-id batch_001 [--batch-id ...] --workers 4
runs only the explicitly selected batches in Slurm, at most four concurrently.
Completed holds/failures remain recorded; this runner does not retry them or
silently dispatch other batches. Source custody failures happen before native
planning and require source recovery rather than unchanged full extraction.

batching.py reconcile MANIFEST RUN_STATE OUTPUT reopens each reviewed plan using
extract_plan.load_plan, including native transport, source and bundle pins.
Local unit IDs are namespaced by batch. Source overlap is rejected. Colliding
reviewed names/scopes, shared collection pages and source-cited publications
nominate cross-batch questions; they never merge methods automatically. The output
always says global_identity_review_required and extraction_authorized=false.
Even no detected collision is not proof of uniqueness: a global review must check
aliases missed by retrieval. Same-scoped-method duplicates need a newly consolidated
source plan before extraction. This final global review runner remains to be wired.
