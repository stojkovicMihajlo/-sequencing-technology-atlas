Operation annotation correction — 4 November 2026

Reason
The inspection_01 audit found rt_pcr_purify in cP-RNA-Seq labelled readout,
although its only output is a physical cDNA library. OperationEffect.aspect
previously enumerated labels without defining each meaning. This is a general
representation problem, not a reason to add technology-specific extraction rules.

Change
representation.py now defines the existing seven effect labels in one shared
text used by the schema and extraction/review instructions. Readout means
obtaining measurement data; preparing a library for later sequencing is not
itself a readout. A validator requires a readout effect to reference at least
one data output. An unrelated data output elsewhere in the operation is not
sufficient. Composite operations may retain material as well as produce data.
No fields, enum values, scientific records or diagram steps were added.

The existing resolution field now explicitly describes source grouping rather
than cross-method equivalence. Different source block boundaries can remain
legitimate. This clarification does not establish a shared-operation matcher.

Reviewer instructions explicitly require tracing States and Flows when a
use_primary correction changes operation order. The current reviewer had already
caught iCLIP's correction/topology disagreement. This prompt clarification is not
a claim that software can prove chronology from arbitrary prose.
