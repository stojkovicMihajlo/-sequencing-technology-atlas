# Clean-input harness validation

The target is a reusable extractor that produces source-grounded method graphs
from registered literature. Repairing an existing graph with a supplied audit is
not evidence that this target works. This experiment starts scSTAMP-seq and
DBiT-seq from source packets alone, using one frozen harness and identical settings.
Both are exposed development cases; no held-out-family claim is made.

The existing pipeline runs fresh candidate-blind source requirements, two readers,
integration and independent source/reader/field review. Its own reviewer can request
one ordinary correction. We supply no previous Workflow, review, requirements,
reference graph or case-specific correction. The plan parser rejects such fields.
No acceptance is inherited. We inspect initial candidates as well as final results;
an error caught by the normal review loop differs from one accepted at export.

The [host evaluation specification](host_evaluation.json) freezes common scientific
questions rather than desired operation names, node counts or a target graph. It
does not enter native prompts. Independent source audit, structural integrity and
consumer usability remain separate outcomes. Positive model verdicts alone do not
establish scientific accuracy. Any next harness revision must address a documented
failure category and receive another clean evaluation; a hand-repaired graph is
not credited as a fresh extraction success.

General safeguards checked before launch:

- Fresh stages require an exact regular-file prompt archive. Missing, altered or
  symlink-substituted prompts fail before supported export.
- The prior DBiT size failure must replay successfully using the existing bounded
  finding reader, without truncating scientific content or increasing the limit.
- Source, reader-finding and factual-field gates are fixed on in the clean runner.
- Plan/source bytes and new output ownership are checked; failures remain results.

The [exact DBiT replay](coverage_size_replay.json) verifies that the old runtime
failed on 18 of 56 single-entry views; the current accessor prepares all 56,
using bound references for those 18. Original descriptions and sampled proposal
rationales were reconstructed exactly; this is not a full scientific review.
The complete development suite passed **2,381 tests, three skipped** before the
freeze. The [plan](plan.json) admits only the two source packets, and the
[source preflight](source_preflight.json) verifies their original bytes and records
procedural locator presence without certifying source closure.

The selected runtime contains code and the extraction contract, with no example
graphs, prior experiments or reference answers packaged beside it. This reduces
accidental exposure; permitted inputs and audited reads are not OS isolation.
Historical sources/paths and failed attempts remain unchanged. The code-only
runtime selection and exact source pins are recorded before Slurm submission.
The default-off shell-environment profile remains off in this experiment.

Native work uses Qiu CPU Slurm, `gpt-6.1-sol` / `xhigh`, the existing Codex login
and managed sandbox/approval policy. No local model job or canonical promotion.
