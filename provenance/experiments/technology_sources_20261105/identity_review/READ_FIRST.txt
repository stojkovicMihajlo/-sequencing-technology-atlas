PAPER AND TECHNOLOGY CURATION — START HERE

Purpose
Resolve what each technology folder denotes and which papers actually support
that method before starting another extraction batch. This is source curation.
It does not approve a protocol, prove a historical edge, or start model runs.

What was checked, and where to look
1. progress/ALL_PAPERS.csv: one row per paper, its title, assigned methods,
   acquisition status, sections actually inspected, finding and remaining review.
   Filter review_status=not_yet_reviewed to see untouched papers.
2. paper_content_review.json: exact abstracts/section locators and hashes supporting
   those inspection notes. A PubMed abstract check is not a full-paper review.
3. decisions.json: every old folder's disposition, source bindings and explanation.
   A duplicate source depiction is not a duplicate assay. Same-paper methods can
   remain separate; the same printed name can denote different methods.
4. reference_bindings.json: selected method-to-paper assignments, source reference
   identifiers, roles and reasons for excluding wrong associations. These are
   candidate curation decisions; scientific inspection can require revisions.
   The original 51265366 mapping is preserved in completed_51265366/. The current
   mapping removes the incorrect MIRA-to-SINE-paper assignment. The published
   candidate folder snapshot and running job still retain their frozen mapping;
   use this current mapping for the next publication, not those older snapshots.
5. progress/AUDIT_PROGRESS.json: reproducible counts from the ledger. Availability,
   abstract checking, full-paper checking and extraction approval stay separate.
